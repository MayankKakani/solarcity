title: MCP

Solarplan supports the Model Context Protocol (MCP) in two ways:

1. **Built-in HTTP endpoint** — every Solarplan instance exposes `/api/mcp` out of the box. No extra setup, no extra process.
2. **Stdio package** (`@solarplan/mcp`) — a local stdio server for clients that prefer stdio transport.

Both offer the same tools for managing workspaces, projects, tasks, comments, and labels.

## Built-in HTTP endpoint

Every Solarplan API instance ships with a Streamable HTTP MCP endpoint. This is the recommended approach for self-hosted deployments.

Point your MCP client at:

```
https://your-solarplan-instance.com/api/mcp
```

On first connect, you will be redirected to Solarplan's login page. After you sign in, all MCP tools run as your authenticated user.

The endpoint implements OAuth 2.1 with PKCE for authentication. Discovery metadata is available at:

- `/.well-known/oauth-protected-resource/api/mcp`
- `/.well-known/oauth-authorization-server/api`

## Stdio package

The `@solarplan/mcp` package runs a local stdio MCP server and authenticates with Solarplan using device authorization. Use this when your MCP client requires stdio transport.

### Prerequisites

- Node.js 20 or newer
- A running Solarplan API
- Access to the Solarplan web app to approve device login

By default, self-hosted Solarplan allows both `solarplan-cli` and `solarplan-mcp` as device auth client IDs.

### Install and register

Use the recommended interactive installer:

```bash
npx @solarplan/mcp
```

The installer lets you choose where to register the server configuration:

- Cursor (user-wide)
- Cursor (project-level)
- Claude Desktop
- Custom JSON config path

You can also run the explicit install command:

```bash
solarplan-mcp install --target cursor-user -y
```

Use `--help` to see all available targets and flags:

```bash
solarplan-mcp install --help
```

### Point to a self-hosted instance

When generating config, pass your Solarplan base URL:

```bash
solarplan-mcp install --target cursor-user -y --api-url https://solarplan.example.com
```

Or set it via environment variable:

| Variable | Description |
| --- | --- |
| `SOLARPLAN_API_URL` | Solarplan API origin. Default: `http://localhost:1337`. Do not include `/api`. |
| `KANEO_MCP_CLIENT_ID` | Device auth client ID. Default: `solarplan-mcp`. |

If you override `KANEO_MCP_CLIENT_ID`, make sure it is included in [`DEVICE_AUTH_CLIENT_IDS`](/core/installation/environment-variables).

### Authentication flow

On the first tool call that needs Solarplan access, the MCP server:

1. Requests a device code from Solarplan
2. Prints a verification URL and user code
3. Opens the browser when possible
4. Polls until you approve sign-in
5. Stores credentials in `~/.config/solarplan-mcp/credentials.json`

## Available tools

Both the HTTP endpoint and stdio package expose the same tools:

- Session: `whoami`, `list_workspaces`
- Projects: `list_projects`, `get_project`, `create_project`, `update_project`
- Tasks: `list_tasks`, `get_task`, `create_task`, `update_task`, `move_task`, `update_task_status`
- Comments: `list_task_comments`, `create_task_comment`
- Labels: `list_workspace_labels`, `create_label`, `attach_label_to_task`, `detach_label_from_task`

## Debugging

To run the stdio server directly:

```bash
npx @solarplan/mcp serve
```

When running from source in this monorepo:

```bash
pnpm --filter @solarplan/mcp run build
pnpm --filter @solarplan/mcp run start
```
